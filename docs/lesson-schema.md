# Схема урока v1

Каждый урок — JSON-документ, соответствующий `docs/lesson.schema.json` (JSON Schema draft 2020-12).
Контент-агент генерирует документ по теме из roadmap.sh, валидирует и кладёт в SQLite;
бот отдаёт только уроки со `status = "published"`.

## Принципы дизайна

1. **Урок = данные, а не текст.** Бот рендерит поля в сообщения Telegram, поэтому на полях
   стоят жёсткие лимиты по длине (см. таблицу ниже) — ни один блок не должен ломаться о лимит 4096.
2. **Квиз машино-проверяемый.** `correct` — это индексы вариантов, а не текст. Бот считает
   XP автоматически, без LLM в рантайме.
3. **Геймификация встроена.** `xp` за урок, бонус за идеальный квиз; `key_terms` пригодятся
   позже как карточки для spaced repetition.
4. **Воспроизводимость генерации.** Блок `meta` фиксирует модель и версию промпта — можно
   перегенерировать урок тем же пайплайном и сравнить версии.
5. **Расширяемость.** `schema_version` в корне; новые поля добавляются минорно, ломающие
   изменения — с bumped версии.

## Поля

| Поле | Тип | Обяз. | Лимиты | Назначение |
|---|---|---|---|---|
| `schema_version` | int | ✅ | = 1 | Версия схемы |
| `id` | slug | ✅ | `^[a-z0-9]+(-[a-z0-9]+)*$` | Стабильный ключ (`internet-what-is-internet`) |
| `roadmap` | obj | ✅ | — | `{roadmap_id, node, category, order}` — привязка к roadmap.sh |
| `language` | str | ✅ | 2 буквы | Язык урока, по умолчанию `ru` |
| `difficulty` | int | ✅ | 1–5 | Сложность |
| `est_minutes` | int | ✅ | 3–30 | Оценка времени прохождения |
| `xp` | int | ✅ | 5–100 | Базовый XP за прохождение |
| `status` | enum | ✅ | — | `draft` → `review` → `published`; `archived` — снят с выдачи |
| `title` | str | ✅ | ≤ 120 | Заголовок |
| `hook` | str | ✅ | ≤ 400 | Хук: зачем это нужно за 1–2 предложения |
| `objectives` | str[] | — | 1–4 × ≤ 200 | «После урока ты сможешь…» |
| `theory` | obj[] | ✅ | 1–5 секций, body ≤ 2500 | Секции `{heading, body}` (markdown); каждая = одно сообщение |
| `key_terms` | obj[] | — | ≤ 8 | Глоссарий `{term, definition}` → будущие карточки |
| `examples` | obj[] | — | ≤ 3 | `{title, body, code?}` — примеры/аналогии, `code` в ```-блоке |
| `practice` | obj | — | — | `{prompt, hint?, solution}` — мини-задание |
| `quiz` | obj[] | ✅ | 3–7 вопросов | `{kind, question, options, correct, explanation}` |
| `pitfalls` | str[] | — | ≤ 5 | Частые ошибки |
| `sources` | obj[] | ✅ | 1–5 | `{title, url}` — минимум 1 (roadmap.sh node) |
| `meta` | obj | — | — | `{generated_at, model, prompt_version, tokens?}` |

## Квиз

- `kind`: `single` (один ответ) или `multi` (несколько). «Верно/неверно» — это `single`
  с двумя вариантами, отдельный тип не нужен.
- `correct`: массив 0-based индексов. `single` → ровно 1; `multi` → 1+.
- Индексы обязаны быть в пределах `options` — JSON Schema это не выразит, проверяет
  валидатор пайплайна (`validate_lesson`), как и правило `kind`/длина.
- `explanation` показывается после ответа (стиль Duolingo).

## Пайплайн статусов

```
draft   — сгенерировано, не проверено
review  — прошло валидацию, ждёт ревью/автопроверки качества
published — доступно боту
archived  — скрыто из выдачи (устарело/заменено новой версией)
```

## Хранение (SQLite)

- Таблица `lessons`: колонки `id`, `roadmap_id`, `category`, `order`, `status`, `difficulty`,
  `language`, `xp` — денормализованы для выборок («следующий урок по треку»).
- Тело урока целиком — в колонке `json` (проверенный документ).
- Ответы пользователя — в отдельной таблице `progress` (не в документе урока).
